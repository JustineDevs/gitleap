## Interactive CLI

After installation, authenticate once and run the normal terminal flow:

```bash
gitleap auth login <token>
gitleap pull https://github.com/owner/repository
```

`pull` renders the live pipeline and opens the interactive dashboard only after
processing reaches `ready`. The compiled `gitleap` binary, not Bun, is the
public client. Local development can run `bun run dev:cli`.

The dashboard supports:

- API-token authentication with a mode-600 session file under `$XDG_CONFIG_HOME/gitleap/session`
- public GitHub URL and revision submission
- live pipeline stage inspection and bounded polling
- cooperative cancellation with a state-version check
- artifact download and archive injection into an existing directory
- keyboard navigation with resize-aware pipeline and explorer grids

The interactive client never executes files from the generated archive. Injection validates archive paths and extracts with ownership metadata disabled.

## Scriptable commands

```bash
gitleap login
gitleap submit https://github.com/owner/repository --revision 40-character-sha
gitleap status <job-id>
gitleap cancel <job-id> --version <state-version>
gitleap download <job-id> --output ./pack.tar.gz
```

All processing commands require an authenticated session. The server authorizes every status, cancellation, and download request from the persisted job access grant; a job ID is not a credential.

## Public states

Clients receive only `queued`, `running`, `ready`, `failed`, `cancelled`, or `expired`. Internal lease, retry, and stage names are not part of the public contract.
